# 偶遇导航（Serendipity Navigation）团队分工

## 成员与角色
- 成员 A：前端负责人
- 成员 B：后端负责人
- 成员 C：项目/演示/文档负责人

## 核心职责

### 成员 A：前端负责人
- 负责网页版页面、交互、状态展示。
- 负责高德地图 JS API 接入、路线与 POI 标注。
- 负责 Loading / Error / Empty / 结果页体验。
- 负责前端测试与打包输出验证。

### 成员 B：后端负责人
- 负责 FastAPI 服务、接口定义与数据清洗。
- 负责高德 Web 服务调用：地理编码、路径规划、POI 搜索。
- 负责绕行计算、规则打分、推荐结果生成。
- 负责后端单测、接口测试与错误降级。

### 成员 C：项目/演示/文档负责人
- 负责需求对齐、里程碑、演示脚本与现场演示。
- 负责更新计划文档、测试清单、README。
- 负责打包/发布/演示环境整理。
- 负责收集现场反馈并排序缺陷。

## 协作方式
- 接口先定字段，再并行开发。
- 后端先提供 Mock 接口，前端先接。
- 每天对齐阻塞项，演示前统一收口。

- 高德 API Key 由谁保管和配置。
- 是否保留 LLM 叙事并统一 fallback 文案标准。
- 现场演示网络环境与备用展示方案。

## 阶段任务与里程碑

### 阶段 1：骨架 + 接口约定
- 成员 A：搭建 Vue 3 + Vite 页面骨架；完成输入页、模式切换、Loading / Error 占位。
- 成员 B：完成 FastAPI 健康检查；定义 `/api/route/recommend` 返回字段；先返回 Mock 数据。
- 成员 C：输出接口字段文档；准备 3 个大连演示场景。

### 阶段 2：核心逻辑 + 地图展示
- 成员 A：接入高德地图；展示路线与 POI；完成结果页基础交互。
- 成员 B：接入高德 Web 服务；完成地理编码、路径规划、POI 搜索、绕行计算、规则打分。
- 成员 C：更新测试清单；开始准备演示脚本与脚本卡。

### 阶段 3：联调 + 降级 + 演示收口
- 成员 A：前后端联调；处理异常态与空结果；做一次完整端到端验证。
- 成员 B：补 LLM 叙事与降级文案；补齐接口测试；做一次压力/超时测试。
- 成员 C：准备现场备份方案；整理 README；确认安装/运行步骤。

### 演示准备：现场验证
- 成员 A：确保移动端浏览器可正常运行；处理现场偶发 UI 问题。
- 成员 B：现场维护后端服务；准备离线/弱网降级方案。
- 成员 C：负责演示流程、时间控制、问题记录与评委问答。

## DoR / DoD

### 通用 DoR
- 需求字段和交互边界已经明确。
- 依赖的高德 API Key、后端地址、演示网络已确认或已有降级方案。
- 负责人清楚阻塞项和备用方案。

### 通用 DoD
- 功能可在本机运行。
- 关键路径有测试或手动验证记录。
- 已更新相关文档或 README。

### 前端 DoD
- 首页可输入起终点并切换模式。
- 结果页可展示推荐结果、额外时间、叙事、POI。
- 地图可渲染路线与标注。
- 异常/空结果有提示，不白屏。

### 后端 DoD
- `/health` 可用。
- `/api/route/recommend` 返回字段完整。
- 高德调用失败时可降级，不直接 500。
- 核心逻辑有单测或接口测试覆盖。

### 项目 DoD
- 计划文档、测试清单、README 已同步。
- 3 个演示场景可复现。
- 现场可快速启动服务并演示。

## Git 协作规则

### 分支策略
- 使用 `main` 作为主分支。
- 功能开发可用特性分支：`feat/xxx`、`fix/xxx`、`docs/xxx`。
- 合并前确保本地可运行并通过相关测试。

### 提交规范
- 建议格式：`type(scope): 简述`。
- 常用 type：`feat`、`fix`、`docs`、`test`、`chore`。
- 示例：`feat(backend): add recommend route endpoint`。

### 协作边界
- 成员 A 主要改 `webapp/`。
- 成员 B 主要改 `backend/`。
- 成员 C 主要改 `docs/` 与项目交付文件。
- 如需跨目录大改，先在群里同步。

### 提交前检查
- 前端：`npm run build` 或至少 `npm run dev` 可启动。
- 后端：`python -m pytest` 通过。
- 不要提交密钥、`node_modules`、缓存文件。

## 现场演示脚本

### 演示顺序
1. 打开网页版首页。
2. 输入起点与终点。
3. 切换探索模式。
4. 展示推荐结果、额外时间、叙事与 POI。
5. 说明“可控的意外”设计理念。

### 备用场景
- 场景 1：大连理工大学 -> 星海广场
- 场景 2：东港 -> 老虎滩
- 场景 3：西安路 -> 傅家庄

### 现场问题预案
- 后端异常：切换离线演示数据。
- 地图加载失败：展示静态路线图或截图。
- 浏览器兼容问题：优先 Chrome / Edge。
