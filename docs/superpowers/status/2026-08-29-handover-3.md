## 第二部分：现有问题（完整清单，按严重程度）

### 1. 前端 3 条测试失败 —— 前三轮从未发现

前三轮跑在 Node 20.12.0 下，`vitest` 根本起不来，所以没人知道这三条是红的。
在 22.23.2 下实测：

```
Test Files  2 failed | 8 passed (10)
     Tests  3 failed | 74 passed (77)

× tests/HomeView.test.js  > submits a demo scenario with its own mode
× tests/PlaceInput.test.js > fills the coordinate when picking a landmark
× tests/PlaceInput.test.js > supports keyboard navigation and selection

AssertionError: expected [['121.5839,38.8816']] to deeply equal [['121.5854,38.9325']]
```

**根因**：`121.5854,38.9325` 是星海广场的**旧错误坐标**（偏真实位置 5.7 km）。
P0-3 那轮把 `constants.js` 里的六个演示坐标全部校正了，但漏改了前端测试里写死的旧值。
所以这不是产品代码的 bug，是**测试没跟上坐标校正**。

**改法**：把测试里的旧坐标换成 `constants.js` 现在的值。不要反过来改 `constants.js` ——
那六个坐标和后端 `dalian.py` 的 `LANDMARKS` 必须逐字节相同，后端
`test_dalian_scenarios.py::test_frontend_constants_match_backend_landmarks` 会钉住这条。

`HomeView.test.js` 那条是同源问题（演示场景的坐标），改法一样，先看它断言的具体值。

#### 【审查修订】要改的是 4 个文件，不是 3 个 —— 漏的那个是 `mock-server.mjs`

上面只列了 3 条失败的单元测试，但同一个 P0-3 漏改还有**第四个文件**，
而它不在 vitest 覆盖范围内，所以 `npm run test:run` 变绿也发现不了：

`webapp/tests/mock-server.mjs:15` 的 `SCENARIOS` 表 key 仍是旧坐标
`121.6068,38.9180->121.5854,38.9325`，而 `constants.js` 演示场景 1 现在发出的是
`121.5197,38.8856->121.5839,38.8816` → **这张表现在从 UI 完全命中不了**。

实测证据（起真实 mock 服务打表，不是读代码推断）：

```
新坐标（演示按钮实际发的）→ pois=1, demo_mode=False, 通用文案   ← 掉进 FALLBACK
旧坐标（表里存的）        → pois=2, demo_mode=True,  「从大工沿海边走…」
```

**后果**：`tests/smoke.mjs` 点的是第一个 `.demo`，然后断言三件只有场景表才给得出的东西 ——
第 63 行 `从大工沿海边走`、第 64 行 `.poi` 数量 `=== 2`、第 66 行 `内置演示数据`。
这三条**必然失败**。它以「40/40 通过」的身份挂在演示前最终回归清单里，
但 smoke 从未在 Node 22 下跑过，所以这个数字是旧的。

**改法**：`mock-server.mjs` 里四处要一起改 —— 第 15 行的表 key、第 25/26 行的
`route.origin` / `route.destination`、第 31 行 `polyline` 的首尾两个点。

**不用动的文件**：`api.test.js`、`geo.test.js`、`ResultView.test.js` 里也有旧坐标，
但那些是任意夹具，不断言真实坐标，改了只会增加噪声。

**验证**：`npm run test:run` 期望 77 passed。改完顺手跑一次后端 `pytest -q`
确认仍是 193 passed（坐标一致性测试会读 `constants.js`）。

**外加一条必跑**（这是本轮新增的纪律）：

```powershell

npm run smoke
```

`npm run test:run` 变绿**不代表**演示路径是通的 —— vitest 覆盖不到 `mock-server.mjs`。
不跑 smoke 就宣布「前端测试修好了」，等于把上面那三条断言留到演示前才炸。

### 4. 后端两处已知取舍（不是 bug，别去"修"）
