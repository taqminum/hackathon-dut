## 本轮修了什么（4 个缺陷）

### 1. 断网演示走不通 —— 本轮最严重的一个

**症状**：评委点「快速体验」的三个演示按钮，断网时会拿到「多花 0 分钟、0 个亮点、
一条两点直线」，看起来像功能没做。

**根因**：`webapp/dist` 里 `DEMO_SCENARIOS` 的坐标和后端 `dalian.py` 的 `LANDMARKS`
差 **4.4–8.4 公里**。后端三张兜底表的 key 是坐标串（4 位小数）拼出来的，
差一个单位（约 11 米）就命中不了 —— 差几公里自然一张都命不中，静默退化成非演示模式。

**为什么之前没发现**：第一轮的离线验证用的是**后端** `dalian.landmark()` 给出的坐标，
而不是**按钮实际发出去**的坐标。两者不一致，所以后端验证全绿、真点按钮却是坏的。
**教训：验证要从用户实际触发的入口取输入，不要从被测代码自己取。**

**改法**：`dist` bundle 按字节替换 12 个点（6 个演示地标 × 2 处 + 大连火车站 +
中山广场 + `MAP_CENTER`），同时同步 `webapp/src/constants.js`。

**验证**：从**打过补丁的 bundle 里正则提取**按钮实际发出的坐标，再逐一打后端：
三场景 × 三模式 9/9 全部 `demo_mode=true`、绕行 2–10 分钟、亮点 ≥ 1、折线 8 点。

### 2. 「景点」匹配不到「风景名胜」

`poi_explorer.py` 有一层本地类型复筛（`if not any(t in poi_type for t in types)`），
把**所有风景类 POI 都筛掉了** —— 高德请求侧的 `types` 接受模糊词「景点」，
但返回侧的分类字符串用的是另一套词表（`风景名胜;公园广场;公园`），
里面根本不含「景点」二字。高德已经服务端筛过一遍，这层本地复筛纯属有害，已删除。

> 第一轮文档里 P1-3b 判「类别名问题不存在」，是因为当时的采样恰好全是餐饮类 POI ——
> 餐饮的返回词表里确实含「餐饮」，所以复筛没杀掉它们。**采样偏差导致的错误结论。**

保留的两道过滤仍然有效：`EXCLUDED_TYPE_KEYWORDS`（拦便利店/烟酒/超市）和 `MIN_RATING = 3.5`。

### 3. 默认模式 `+5` 完全不看评分

`_choose_candidate` 对 `+5` 取 `min(detour_minutes)`，而候选**在更早的
`_evaluate_candidate` 里已经按预算过滤过一次**了 —— 于是评分这一维在默认模式下
完全不参与决策，选出来的是「绕行最少」而不是「最值得」。

改成三个模式一视同仁：**预算内取 `max(score)`，并列时绕行少的优先**（破平，保证
结果不依赖候选顺序）。因为预算过滤在前，取 max 不可能超出模式上限。

### 4. geocoder 没有城市偏置

原来只用 Nominatim，把「老虎滩」解析到**新西兰**、「星海广场」解析到**西藏**。
改成高德 `/v3/geocode/geo` 带 `city=大连` 优先，Nominatim 退为兜底并加
`viewbox` + `bounded=1` 限定在大连。坐标输入直接短路，不发网络请求。

现在老虎滩、星海广场、大连理工都落在大连境内（经度 121.4–121.9，纬度 38.8–39.1）。

## ⚠️ 最大技术债：`webapp/dist` 是手工改的

Node **v20.12.0** 跑不了 `npm run build`（vite/rolldown 要求 `^20.19.0`），
所以 dist bundle 是**直接按字节改的，没有重新构建**。

`dist/assets/index-AghV8086.js` 改了三处：

1. 12 个演示坐标（等长替换，长度不变）
2. `ScoreMeter` 的 `max`/`segments`：`10` → `7`
3. 「额外时间」的 hint：绕行为 0 时换文案

字节数 255829 → 255879，sha256 开头 `da7cdf2d`。每处都做了「出现次数断言 +
改完 `node --check`」。等长替换只对第 1 处是刻意的；`index.html` 只按文件名引用
bundle，没有 sourcemap、没有 SRI `integrity`，所以第 2、3 处改长度也安全。

**下一个人必须知道：**

- **任何一次 `npm run build` 都会覆盖这三处补丁。** 对应的源码改动都已经同步做过了
  （`constants.js` / `ScoreMeter.vue` / `ResultView.vue` / `format.js`），
  所以升完 Node 重新构建一次，产物应该等价 —— 但**构建完必须重跑下面两条验证**。
- **`constants.js` 里那六个演示地标的坐标串，必须和 `dalian.py` 的 `LANDMARKS`
  逐字节相同**。两个文件里都写了互相指向的注释，别只改一边。
  `DALIAN_LANDMARKS` 另外两条「大连火车站」「中山广场」不在后端表里，只是输入框
  快捷项，不参与兜底匹配，坐标是本轮用高德地理编码查的，**没有实地核过**。


### 前端测试怎么跑（重要，有坑）

`npx vitest run` 在 Node v20.12.0 上**直接起不来**，两个独立的阻塞点：

1. rolldown 调 `util.styleText(['underline','gray'], ...)`，v20.12 的 `styleText`
   不接受数组 → `ERR_INVALID_ARG_VALUE`。
2. jsdom 29 要求 Node `^20.19.0`，会抛 `require() of ES Module`（`html-encoding-sniffer`）。

第 1 个可以用 `node:util` 补丁绕过（本轮临时补丁写在 `%TEMP%\shim\`，**是临时文件，
可能已经没了；需要的话照下面重写一个**）：

```js
// hooks.mjs：把 node:util 重定向到打了补丁的版本
// util-patch.mjs：styleText 遇到数组时逐个 reduce 应用
// 用法：NODE_OPTIONS="--import file:///.../register.mjs" npx vitest run --environment=node --pool=threads
```

第 2 个绕不过去 —— **组件用例（HomeView/ResultView/MapView/PlaceInput/App）
在本机无法运行**。所以本轮的 UI 改动是用 **playwright 真浏览器**验证的
（jsdom 装不了，但 playwright 1.62.1 + chromium 二进制是好的）：
指向后端托管的**打过补丁的 dist**，断言评分条显示 `/7` 且按 7 分制填格、
绕行 0 时 hint 换文案、掐掉瓦片后折线和亮点照常渲染、控制台无报错。

> 掐瓦片必然产生 `ERR_FAILED` 控制台错误，那是验证脚本自己造的。
> 判断「控制台无报错」时要把自己 abort 的 URL 排除掉，否则会误报。

**结论：要动前端就先升 Node 到 20.19+ / 22.12+，别在演示当天升。**

  改成命中具体子类目就不记父类目（`BROAD_TAGS` = {餐饮, 购物}），
  跟 `TAG_KEYWORDS` 上那条「从具体到宽泛，第一个命中的关键词决定类目」的注释一致。
  只命中父类目的（`餐饮服务;餐馆`）仍然落到「餐饮」，不会退化成「其它」。
  `tests/test_preference.py` 9 个用例，核心那条断言咖啡反馈后
  `affinity("餐饮服务;海鲜酒楼") == 0.0`。
  **为什么要紧**：这正好是演示时那个问题「点了不喜欢之后呢」的答案。
- **`/api/preference` 的 mode 是陈旧的** —— `_mode` 过去只有 `/api/feedback` 会写，
  所以连点三次 +15 之后这个证据接口还显示 `+5`。改成 recommend 校验通过后立刻记下。

**第二轮 review：同一个 bug 的第二个实例（共享桶）**

第一次只修了 `BROAD_TAGS` 那一半，漏了 `UNKNOWN_TAG`。「其它」当时扮演的角色
跟修复前的「餐饮」完全一样 —— 一个共享桶：点一次「不喜欢」某个度假场所，
药店、酒店、电影院会一起沉底（各 -0.333）。

按高德真实分类打表量过：共享的「其它」横跨 **7 个互不相关的大类**
（体育休闲、医疗保健、住宿、生活服务、商务住宅、交通设施、金融保险）。
改法是让未知类型按自己的**大类**（type 串第一段）单独成桶，反馈仍然落得下去，
但只影响同一类。只有连 type 串都没有（None / 空串 / 非字符串）时才回到共享的「其它」。

`test_preference.py` 原来有一条测试正在断言这个错误行为
（`assert manager.affinity("另一种没见过的") < 0`），已改掉。

**TAG_KEYWORDS 里其余的多对一合并逐个查过**，结论是有意的、不是同一个 bug：
「面包/蛋糕 -> 烘焙」「快餐/小吃 -> 小馆」「购物/商场 -> 购物」都落在单一大类内，
是同义词归并；「风景」（风景名胜 + 旅游景点）和「人文」（科教文化 + 书店）
确实跨大类，但那是**刻意**的 —— 高德把同一批景点分散在两个大类下，
书店在分类体系里挂购物下但用户心里跟博物馆是一类。
两者都在测试里写成显式白名单 `INTENTIONAL_CROSS_CATEGORY_TAGS`。

补了**两条结构性卫兵**，各覆盖渗漏的一种形状（缺一条就漏一个实例）：
跨大类聚合检查抓「其它」型，具体/宽泛并存检查抓「餐饮」型。
以后往 TAG_KEYWORDS 加词会自动被覆盖。
